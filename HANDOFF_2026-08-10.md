## 1. Contraintes posées par l'utilisateur — elles priment sur tout

1. **Univers imposé, sans exception** : `NAS100, US500, US30, GER40, FRA40, XAUUSD`.
   Toute stratégie est testée **sur les six**, même quand son auteur écrit qu'elle ne
   marche que sur un marché. *(Aussi consigné dans `wiki/SCHEMA.md`.)*
2. **Intraday uniquement** : sortie forcée avant la clôture de séance (un `deadline` par
   entrée, pas un plafond de N barres).
3. **Ne pas se servir du taux de hasard comme filtre.** On teste tout ce qui est
   intéressant et on rapporte les résultats bruts. *(Le placebo reste calculé — voir §5 —
   mais comme étalon, jamais comme porte.)*
4. **Pas de données externes** (macro, VIX, news, sentiment, order book, iCustom).
5. **Si un script réclame un timeframe absent du cache, le rapatrier depuis Pepperstone
   MT5** — vaut pour tous les travaux.
6. Absence de SL dans le script ≠ rejet : **on fournit le bracket** (ATR et structure).

## 4. ⛔ LE BLOCAGE — à traiter en premier

`edgelab/intraday/adx_di.py` **ne reproduit pas** le portage transpilé qui a produit ces
chiffres :

| | accord signal | R/an | maxDD | RoMaD |
|---|---|---|---|---|
| GER40 mesuré (transpileur) | — | +14,27 | 12,8 | **1,12** |
| GER40 module repo | 98,36 % | +12,94 | 19,2 | **0,67** |
| NAS100 mesuré | — | +15,27 | 23,6 | 0,65 |
| NAS100 module repo | 98,62 % | +4,66 | 36,8 | **0,13** |

1,6 % de désaccord suffit à changer la stratégie. **Rien n'a été déployé.**

**Deux causes candidates**, documentées dans le module :
1. amorçage du lissage de Wilder sur la chaîne DX→ADX, face à `scratchpad/mt4_indicators.py`
   (que le transpileur utilise) ;
2. le **décalage d'une barre** sur le plancher de spread — `kauf_lib.Table` applique
   `floor_spread × spread[i−1]` (valeur connue à la décision), le module le plie dans la
   distance **sans** ce décalage.

**Méthode** : comparer `adx_di()` à `mt4_indicators.adx()` barre par barre sur GER40 M15,
corriger, re-mesurer. Si RoMaD revient à 1,12 → câblage live mécanique (mirroir de
`KaerStrategy`, magic **108**, `enable_adxdi`, 0.5R, + un contrôle dans
`edgelab/live/verify.py` — **aucune sleeve ne part sans son verify**).
Si RoMaD reste à 0,67 → **il n'y a plus de candidat** et la campagne conclut à zéro.

Règle source (lue dans `scratchpad/_corpus/mt4/8830/ADX_System.mq4`) :
```
LONG  si ADX[2]<ADX[1] et +DI[2]<ADX[2] et +DI[1]>ADX[1]
SHORT si ADX[2]<ADX[1] et -DI[2]<ADX[2] et -DI[1]>ADX[1]
```
⚠️ **Ce n'est PAS « ADX_System.mq4 »** : l'EA d'origine n'a aucune logique de séance et un
bracket fixe 30/100 points. Ce qui est validé, c'est **sa condition d'entrée dans le
dispositif intraday du projet**. Ne pas laisser le nom circuler.

## 5. ⭐ LE PROCHAIN RUN

```bash
python -u scratchpad/battery_all.py 2
```

Batterie complète sur **tous** les signaux ayant au moins une cellule t>2 (aucun
pré-filtre — correction demandée par l'utilisateur), **plus une cohorte placebo appariée**
(même nombre d'entrées, même fraction longue, mêmes barres éligibles).

Le chiffre décisif n'est pas le nombre de survivants mais **survivants réels / survivants
placebo** : ≫1 = edge dans la cohorte ; ≈1 = ce que la chance produit, quel que soit le
nombre de tests passés. *(Le ledger enregistre qu'une short-list choisie sur un null
repasse son propre null 81 % du temps — c'est pourquoi le placebo est indispensable même
si on ne filtre sur rien.)*

Sortie : `scratchpad/_inx/battery_all.csv`.

**⚠️ Le lancer en tâche SUIVIE par le harnais** (une par appel), pas en `nohup ... &` :
deux runs ont été perdus aujourd'hui parce que le harnais ne suivait que l'enveloppe.
